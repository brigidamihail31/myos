# 07. Тест-план учебной ОС MyOS

## 1. Введение

Цель тестирования — убедиться, что учебная ОС MyOS корректно выполняет
заявленные функции, соответствует нефункциональным требованиям из матрицы
трассируемости и устойчива к ошибочным действиям пользователя.

Область применения: локальный запуск на Python 3.10+ с SQLite,
в рамках учебной практики УП.02 (разделы 1–3).

## 2. Объём тестирования

### Входит в объём
- модульное тестирование каждой функции `db.py`, `kernel.py`, `auth.py`,
  `fs.py`, `scheduler.py`;
- функциональное тестирование системных вызовов `syscalls.py`;
- интеграционное тестирование связок
  `shell → syscalls → fs`, `shell → syscalls → scheduler`,
  `shell → syscalls → auth`;
- системное тестирование сквозных сценариев работы ОС;
- регрессионное тестирование после исправления дефектов.

### Не входит в объём
- тестирование производительности под высокой нагрузкой;
- тестирование на реальном аппаратном обеспечении;
- тестирование сетевых сценариев;
- тестирование графического интерфейса (его нет).

## 3. Виды тестирования

Применяются следующие виды:
- модульное — для каждой отдельной функции;
- функциональное — для системных вызовов;
- интеграционное — для связок
  `shell → syscalls → fs`, `shell → syscalls → scheduler`;
- системное — для сквозных сценариев;
- регрессионное — после каждого исправления дефекта.

## 4. Ресурсы

**Инструменты:** VS Code, Python 3.10+, SQLite, SQLite Viewer, Git.
**Документация:** матрица трассируемости из `03_Module_Specifications.md`.
**Тестовые данные:** создаются скриптами, ручной подготовки не требуют.

## 5. Расписание

| День | Что делается |
|---|---|
| 7 | Разработка стратегии, тест-плана, тест-кейсов, модульных тестов |
| 8 | Функциональное и интеграционное тестирование |
| 9 | Системное и регрессионное тестирование, итоговый протокол |

## 6. Критерии

**Критерии начала:** все модули реализованы, интеграционные тесты проходят,
отчёт о разработке сдан.

**Критерии окончания:**
- все модульные тесты проходят;
- все функциональные тесты проходят;
- все интеграционные тесты проходят;
- все системные сценарии выполнены;
- найденные дефекты зафиксированы в баг-репортах;
- требования верифицированы по матрице трассируемости;
- итоговый протокол оформлен.
